1 Business Problem & Objective

The enterprise has thousands of internal documents (policy PDFs, technical manuals, SOPs, incident reports, KB articles, structured database tables, and cross-system entity relationships). Employees cannot reliably find accurate answers.

Leadership Challenges

  • Employees struggle to find accurate information quickly
  • Knowledge is scattered across disconnected systems
  • Existing search fails on complex, multi-hop queries
  • High dependency on internal experts slows decision-making
  • No mechanism to validate AI responses for safety & compliance
  • Lack of observability and evaluation in AI systems

Objective — the assistant must:

  • Retrieve accurate, cited information from enterprise data
  • Combine vector + graph retrieval with re-ranking
  • Use agent-based reasoning and tool execution
  • Apply multi-layered guardrails (input → output)
  • Provide observability, evaluation and performance monitoring

4 Data Layer & Ingestion Pipeline

Offline, idempotent pipeline (re-runnable via POST /ingest or CLI). Uses dummy or public data, as allowed by the scenario.

Unstructured

  • PDF documents (policies, manuals)
  • Markdown / text files (SOPs, incident reports)
  • FAQ knowledge base

→ load, clean, chunk, embed → ChromaDB + BM25 index

Structured

  • CSV / SQL tables (products, users, transactions)
  • Metadata tables

→ loaded into SQLite / Postgres; queried by the agent's read-only SQL tool

Graph

  • Entities: people, systems, components
  • Relationships: DEPENDS_ON, OWNS, RELATED_TO

→ LLM-based entity/relation extraction → Neo4j, with links back to source chunks

5 Hybrid Retrieval Strategy (Vector + Graph)

Vector search alone fails for multi-hop questions such as "Which teams are affected if the payment gateway's auth service fails, and what SOP applies?" The graph answers the relationship part. Vector and BM25 search find the content.

① Vector Search

Dense similarity in ChromaDB, top-20, with metadata where filters.

semantic

② Keyword (BM25)

Exact matches for IDs, error codes and product names that embeddings miss.

lexical

③ Graph Traversal

Entity linking on the query → 1–2 hop Cypher expansion → related entities + linked chunks.

multi-hop

④ Fuse + Re-rank

Reciprocal Rank Fusion, then cross-encoder (e.g. bge-reranker) → top-5 with scores.

precision
# retrieval/hybrid.py  (conceptual)
def hybrid_search(query, filters=None, k=5):
    vec   = chroma.query(embed(query), n_results=20, where=filters)
    kw    = bm25.search(query, top_n=20)
    ents  = entity_linker(query)                       # ["Payment Gateway", "Auth Service"]
    graph = neo4j.run("MATCH (e)-[r*1..2]-(n) WHERE e.name IN $ents RETURN e,r,n", ents=ents)
    fused = reciprocal_rank_fusion([vec, kw, graph_to_chunks(graph)], k=60)
    return cross_encoder.rerank(query, fused)[:k]      # each hit -> {text, source, page, score}

6 LangGraph Agent Workflow

A state machine with conditional edges: route → retrieve and/or use tools → generate → self-check → guard. Shared AgentState carries messages, retrieved docs, tool results, citations and retry count.

Tools

ToolPurposeSafety control
Web SearchPublic / recent info (e.g. Tavily, DuckDuckGo)Domain allow-list, result size cap
SQL QueryProducts, users, transactions tablesRead-only connection, SELECT-only parser, row limit
Python ExecutionCalculations, data analysis, chartsSandboxed subprocess, timeout, no network / FS write
MCP IntegrationsStandardised access to external systems (ticketing, wiki, file stores)Per-server scopes, audit log
Knowledge RetrievalHybrid RAG exposed as a tool for multi-step plansMetadata filters, top-k cap

Agent State

class AgentState(TypedDict):
    session_id:   str
    messages:     list[BaseMessage]   # session memory
    query:        str                 # sanitized
    route:        Literal["rag","agent","direct"]
    model_tier:   Literal["fast","strong"]
    documents:    list[Document]
    tool_results: list[dict]
    answer:       str
    citations:    list[Citation]
    grounded:     bool
    retries:      int
    guard_flags:  list[str]

7 Multi-Layered Guardrails

Defence in depth: checks run before the LLM, during agent execution, and after generation. Every block or redaction is logged to Langfuse as a scored event.

LayerCheckTechniqueAction on failure
InputInput validationPydantic schema, length / charset limits, empty / garbage detection400 with reason
InputPrompt-injection / jailbreakHeuristic patterns + classifier (e.g. LLM-Guard / small LLM judge)Refuse, flag trace
InputPII detection & maskingMicrosoft Presidio (email, phone, SSN, card, names) → placeholder tokensMask before LLM / logging
InputTopic / policy scopeAllowed-domain classifier (enterprise knowledge only)Polite out-of-scope reply
ExecutionTool safetySELECT-only SQL, sandboxed Python, web allow-list, max agent stepsAbort tool call
GenerationHallucination checkLLM-as-judge faithfulness vs. retrieved context + citation presenceRetry with rewritten query, or "insufficient evidence"
OutputPII leakagePresidio re-scan of the final answerRedact
OutputToxicity / unsafe contentModeration model / classifierReplace with safe response
OutputPolicy & format complianceCitations required, JSON schema, no secrets / internal promptsRegenerate / fix format

8 Production Infrastructure

FastAPI Serving

  • POST /chat — main Q&A endpoint
  • POST /ingest — (re)index the corpus
  • GET /health — liveness / dependency checks
  • GET /sessions/{id} — conversation history
  • Async handlers, Pydantic models, Uvicorn workers

Semantic Caching

  • Embed the query, then nearest-neighbour lookup in the cache collection
  • Hit if cosine similarity ≥ 0.92 and corpus version matches
  • TTL plus invalidation on re-ingest
  • Only answers that pass the guardrails are cached

Model Routing

  • Fast / cheap model: classification, simple FAQ, grading
  • Strong model: multi-hop, agentic, long-context synthesis
  • Fallback to a secondary provider on errors / timeouts
  • Cost per request tracked in Langfuse

9 Observability & Evaluation

🔭 Langfuse Observability

  • One trace per request; spans for guardrails, cache, router, retrieval, rerank, tools, LLM calls
  • Tracks latency (per span and P50/P95), token usage, cost, errors
  • Scores attached: guardrail flags, faithfulness, user feedback
  • Prompt versioning; dashboards and screenshots for the deliverables

🧪 Promptfoo Test Suite (30+ cases)

  • Factual RAG Q&A with expected facts / citations (contains, llm-rubric)
  • Multi-hop graph questions
  • Tool-use cases (SQL aggregates, calculations, web)
  • Adversarial: injection, jailbreak, PII extraction, off-topic
  • Runs as a regression suite in CI; failures analysed per category
